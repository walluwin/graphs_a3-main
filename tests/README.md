# My tests

| File | What it is |
|---|---|
| `verify.py` | test runner: cases with answers derived by hand + semantic checkers + mixed/reset run + checker self-test + large inputs |
| `my_cases.jsonl` | inputs of the small cases (generated by `verify.py`) |
| `actual_output.jsonl` | actual answers of the program for `my_cases.jsonl` (same line order) |
| `mixed_cases.jsonl` | all cases, reversed, all again - one process, checks state reset |
| `RouteTest.java` | test of the route-reconstruction helper |

## Commands (from the repository root)

```sh
python tools/run.py --check                 # 36 public checks + state reset
python tests/verify.py                      # my small cases, mixed batch, checker self-test
python tests/verify.py --large              # + inputs with n=100000, m=250000 and deep chains (seed 20261024)
python tools/run.py --input tests/my_cases.jsonl
javac -d .build/routetest src/Java/*.java tests/RouteTest.java
java -cp .build/routetest RouteTest
```

Expected answers: every case in `verify.py` has `expect` (values computed by hand, the reasoning is in the
comment/note of the case). Answers that may differ (forest ids, SCC labels, topological order, parent edges)
are validated by meaning, not by equality.
